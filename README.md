# AI Creative Studio

استوديو إبداعي عربي أولًا بالذكاء الاصطناعي. **المرحلة الأولى**: الأساس + أول مسار MVP
(مشروع جديد ← فكرة/نص ← نص ← مشاهد ← لوحة قصة قابلة للتعديل)، كله محلي ومجاني وبمزوّدات وهمية.

## التشغيل

```bash
npm install
npm run dev        # http://localhost:3000
npm test           # اختبارات الوحدة والتكامل (Postgres في الذاكرة)
npm run typecheck
npm run worker     # عامل المهام (أوقف التطبيق أولًا عند استخدام PGlite المحلي)
```

لا يحتاج أي مفتاح API ولا خادم قاعدة بيانات: PostgreSQL حقيقي يعمل داخل العملية عبر PGlite ويُحفظ في `.data/`.
المخطط `src/db/migrations/001_init.sql` هو SQL خالص لـPostgres يعمل كما هو على Supabase لاحقًا.

## البنية

```
src/
  config/       إعدادات المنصات (platform-presets) ونقاط البداية بحالتها الصادقة (start-options)
  db/           عميل قاعدة البيانات + الترحيلات (SQL خالص)
  providers/    واجهات المزوّدين: نص، صورة، فيديو، صوت، تحويل كلام، مزامنة شفاه، موسيقى
    mock/       مزوّد وهمي لكل واجهة، بلا شبكة ولا تكلفة
    registry.ts الموجّه: يختار المزوّد حسب القدرة ودرجة الجودة
  lib/          المشاريع، المشاهد، الأصول والتخزين، طابور المهام، سجل التكلفة
  app/          واجهة Next.js عربية RTL + server actions + مسار تقديم الأصول
scripts/worker.ts  عامل طابور المهام
tests/          اختبارات Vitest
```

## مبادئ

- كل توليد مهمة مستقلة في Postgres، تُعاد وحدها عند الفشل، والمدخلات المتطابقة يُعاد استخدام نتيجتها دون تكلفة.
- كل استدعاء مزوّد (حتى الوهمي) يُسجَّل في `provider_calls` بكميته وسعره.
- كل زر غير منفّذ معطّل ويحمل «قريبًا» أو «يحتاج مزوّدًا».
- إضافة مزوّد حقيقي = ملف محوّل واحد + سطر في `registry.ts`، وبعد موافقة صريحة فقط.
